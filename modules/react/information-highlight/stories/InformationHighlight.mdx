# Canvas Kit Information Highlight

A container to call out important information on a page or a section of a page that the user should
be aware of.

## Installation

```sh
yarn add @workday/canvas-kit-react
```

### Variants

`InformationHighlight` has four variants and each `variant` has two types of `emphasis`.

Variants: `default`, `informational`, `caution`, `critical`

Emphasis: `low`, `high`

The variants have different icons and colors to convey severity and the emphasis changes the
background color to have a lower or higher contrast. If no `variant` or `emphasis` is selected the
layout will default to `Variant: default, Emphasis: low`.

The following examples will show the `low` and `high` emphasis of the severity variants. `low`
Emphasis will be shown first and should be used when there is other more important information on
the page. `high` Emphasis will be shown second, and should be used when the highlight is not
competing with other, more important information.

#### Default

The default variant is for general callouts that do not convey a specific severity level. See the
[Basic Example](#basic-example) above — it uses the default `variant` and `emphasis` with all parts
filled in.

#### Informational

The informational variant is for _nice to have_ information, such as related features or

### Link Text Guidance

When you include `InformationHighlight.Link`, write labels for quick scanning in the highlight
layout.

- **Keep link text concise and scannable** — Use the shortest meaningful phrase.
- **Prevent wrapping** — Avoid sentence-length links in tight layouts.

### Action Placement

Use `actionPlacement` to control where the link renders relative to the heading and body.

- `bottom` (default): the link stacks below the heading and body in document order.
- `end`: the link renders beside the content (when the component is wide enough), vertically
  centered at the inline end; in narrower widths it moves below the body, still aligned to the
  inline end.

> **Note**: `actionPlacement` only changes placement in the component's CSS grid. Keyboard tab
> order and screen reader order stay unchanged (**Heading → Body → Link**). With
> `actionPlacement="end"`, the link appears at the inline end when the highlight container is wide
> enough. At narrower widths, it stacks under the body while remaining last in the DOM. Use the
> width controls in [Action Placement End](#action-placement) to preview reflow.

With `actionPlacement="end"`, long link text wraps within the available width rather than
truncating, and the layout reflows when the highlight is narrow. `end` uses the logical inline end,
so placement follows reading direction in RTL layouts (see [RTL Example](#rtl-example)). See
[Link Text Guidance](#link-text-guidance) for copy guidance.
