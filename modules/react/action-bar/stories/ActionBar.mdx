# Canvas Kit Action Bar

Action Bar is a [compound component](/get-started/for-developers/documentation/compound-components/)
that contains primary and secondary actions related to a page or task.

[> Workday Design Reference](https://design.workday.com/components/buttons/action-bar)

## Installation

```sh
yarn add @workday/canvas-kit-react
```

## Usage

### Basic Example

`ActionBar` includes a container `ActionBar` component and the following subcomponent:
`ActionBar.List` which should contain `ActionBar.Item`.

In a basic example of an `ActionBar` there are two buttons. The primary action button should be used
only once and left aligned if content is left to right, followed by secondary buttons. Tertiary
buttons should not be used in the Action Bar.

### Icons Example

`ActionBar.Item` renders a `SecondaryButton` as default, so it's possible to use other Button props
with `ActionBar.Item` such as `icon` or `size`.

<ExampleCodeBlock code={Icons} />

### Delete Action Example

`ActionBar.Item` is a `SecondaryButton` by default but it's possible to change it to another
element, such as `DeleteButton`, by using `as` prop.

<ExampleCodeBlock code={DeleteAction} />

### Overflow Example

`ActionBar` container can contain up to 3 actions and an Overflow Menu if there are more than 3
actions, the other remaining actions should be placed into an Overflow Menu that is launched by
clicking the Overflow Button.

Also, ActionBar is a responsive component based on the width of its container. If the rendered
actions exceed the width of the `ActionBar.List`, an overflow menu will be rendered. This only works
against the dynamic API where you give the `ActionBarModel` an array of items to be rendered. The
dynamic API handles the React `key` for you based on the item's identifier. The dynamic API requires
either an `id` on each item object or a `getId` function that returns an identifier based on the
item. The below example uses an `id` property on each item.

The dynamic API takes in any object, but since nothing is known about your object, a
[render prop](https://reactjs.org/docs/render-props.html) is necessary to instruct a list how it
should render.

<ExampleCodeBlock code={OverflowActionBar} />

The number of visible buttons can also be adjusted by using the model's `maximumVisible` attribute.
You can change it from the default of 3 to any number greater than 1 and less than items.length.

## Accessibility

The primary accessibility goal is a clearly named group of page-level actions where every action is
a native, keyboard-operable button. Use Action Bar for the primary and secondary actions of a page
or task. For a single action, use a [Button](/components/buttons/button/#accessibility) directly.

Overflow in Action Bar uses [Menu](/components/popups/menu).

For actions that open a modal or dialog, compose [Modal](/components/popups/modal) or
[Dialog](/components/popups/dialog) from an **`ActionBar.Item`** (see **Dialog/Modal trigger
composition** in Accessibility Requirements below).

When actions overflow, keyboard and assistive technology behavior follow Canvas Kit
[Menu](/components/popups/menu/#accessibility). For broader guidance, see the Canvas Kit
[Accessibility overview](https://workday.github.io/canvas-kit/?path=/docs/guides-accessibility-overview--docs).

### Minimum Accessible Structure

The following matches the [Basic Example](#basic-example): an **`ActionBar.List`** rendered as a
labelled `section`, with a primary action first and secondary actions after it. **`ActionBar.List`**
and **`ActionBar.Item`** should always be inside **`ActionBar`**.

```tsx
import {ActionBar} from '@workday/canvas-kit-react/action-bar';
import {PrimaryButton} from '@workday/canvas-kit-react/button';

<ActionBar>
  <ActionBar.List position="relative" as="section" aria-label="Action Bar">
    <ActionBar.Item as={PrimaryButton} onClick={() => console.log('first action')}>
      First Action
    </ActionBar.Item>
    <ActionBar.Item>Second Action</ActionBar.Item>
  </ActionBar.List>
</ActionBar>;
```

Provide a translated, descriptive **`aria-label`** on **`ActionBar.List`**. Every
**`ActionBar.Item`** needs non-empty visible text, which becomes its accessible name.

### Built-in Behaviors

Canvas Kit applies these automatically. **Do not duplicate them** in consuming code.

**ARIA and DOM** (_applied by hooks/subcomponents_):

- **`ActionBar.Item`**: Defaults to **`SecondaryButton`**, which renders a native
  `<button type="button">` with native keyboard behavior. Visible text provides its accessible name.
  When overriding **`as`**, preserve the semantics required by that component.
- **Overflow**: Items that do not fit, or that exceed `maximumVisible`, receive `aria-hidden`,
  `inert`, and `disabled`, so they are removed from the tab order and the accessibility tree and
  appear in the overflow menu instead.
- **`ActionBar.OverflowButton`**: Renders a **`SecondaryButton`** with the related-actions icon,
  `aria-haspopup`, and `aria-expanded` through the **`Menu.Target`**. It is `aria-hidden` with
  `tabIndex={-1}` while no items overflow, and gains `tabIndex={0}` once items overflow.
- **`ActionBar.Menu`**: The standard [Menu](/components/popups/menu/#accessibility) API (`ActionBar`
  shares one menu model with **`ActionBar.OverflowButton`**).

**Keyboard** (_native `<button>` behavior_):

Visible **`ActionBar.Item`** components use native `<button>` keyboard support: each item is its own
tab stop (<kbd>Tab</kbd> / <kbd>Shift</kbd>+<kbd>Tab</kbd>), and <kbd>Enter</kbd> or
<kbd>Space</kbd> activates it. Action Bar does not use roving tabindex. Overflow menu behavior
follows [Menu accessibility](/components/popups/menu/#accessibility); **`ActionBar.OverflowButton`**
is the menu target.

Keyboard focus and screen reader reading order follow **DOM order** among visible
**`ActionBar.Item`** components and **`ActionBar.OverflowButton`**, not the fixed visual position of
the bar on the viewport.

**Screen reader expectations** (_when built-in behaviors are used as intended_):

- On entering the group, the landmark is announced with the **`aria-label`** (for example, "Action
  Bar, region").
- Each visible item is announced by its text and role (for example, "First Action, button").
- The overflow button is announced with its **`aria-label`** and as a menu button with expanded or
  collapsed state (for example, "More actions, menu button, collapsed").
- Items moved into the overflow menu are no longer announced as buttons in the bar. They are
  announced as menu items when the menu is open.

### Accessibility Requirements

Required in application code for an accessible Action Bar. Rows marked _(conditional)_ apply only
when the situation matches—otherwise omit.

**If no design spec is provided:** render **`ActionBar.List`** with `as="section"` and a translated
**`aria-label`**, and **`ActionBar.Item`** components with visible text. Reserve space so the fixed
bar does not cover page content or focused controls. Omit an icon-only item, a dialog or modal
trigger, an overflow button, and **`disabled`** unless the spec requires them.

| Requirement                             | How to satisfy                                                                                                                                                                                                   |
| --------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Group label                             | `as="section"` and a translated **`aria-label`** on **`ActionBar.List`** that is unique among landmarks on the page                                                                                              |
| Item accessible name                    | Non-empty visible text as the child of every **`ActionBar.Item`**                                                                                                                                                |
| Icon-only name _(conditional)_          | When the spec requires an icon-only **`ActionBar.Item`**, wrap it in **`Tooltip`** with **`title`** and `type="label"` (preferred), or set **`aria-label`** on the item when the spec says not to use a tooltip. |
| Dialog or modal trigger _(conditional)_ | See **Dialog/Modal trigger composition** below, and the popup component’s accessibility section                                                                                                                  |
| Overflow button name _(conditional)_    | Translated **`aria-label`** on **`ActionBar.OverflowButton`**, passed through **`overflowButton`** on **`ActionBar.List`**                                                                                       |
| Focus not obscured                      | Reserve space (padding, spacer, or layout) so the fixed **`ActionBar.List`** does not cover page content or focused controls                                                                                     |
| Disabled action _(conditional)_         | Native **`disabled`** on **`ActionBar.Item`** when the spec marks the action unavailable                                                                                                                          |

#### Dialog/Modal trigger composition _(Conditional requirement)_

Place **`Dialog`** or **`Modal`** (whichever matches the design) inside **`ActionBar.List`**,
wrapping only the bar action that opens it. Render that action as
**`Dialog.Target as={ActionBar.Item}`** or **`Modal.Target as={ActionBar.Item}`** so the popup model
owns open, close, and focus while the item still registers with the Action Bar. Other
**`ActionBar.Item`** components stay siblings outside the popup container.

```tsx
import {ActionBar} from '@workday/canvas-kit-react/action-bar';
import {Dialog} from '@workday/canvas-kit-react/dialog';

<ActionBar>
  <ActionBar.List position="relative" as="section" aria-label="Action Bar">
    <Dialog>
      <Dialog.Target as={ActionBar.Item}>Create</Dialog.Target>
      <Dialog.Popper>
        <Dialog.Card>
          <Dialog.Heading>Create</Dialog.Heading>
          {/* Dialog.Body, actions — see Dialog accessibility */}
        </Dialog.Card>
      </Dialog.Popper>
    </Dialog>
    <ActionBar.Item>Cancel</ActionBar.Item>
  </ActionBar.List>
</ActionBar>;
```

**Summary for code generation:**

- **REQUIRED:** **`ActionBar.List`** with `as="section"` and a translated **`aria-label`**; every
  **`ActionBar.Item`** with visible text; reserve space so the fixed bar does not cover page content
  or focused controls
- **CONDITIONAL:** icon-only **`Tooltip`** / **`aria-label`** naming; **`Dialog`** / **`Modal`**
  composition; **`overflowButton`** with an **`aria-label`**; **`disabled`** when the spec marks an
  action unavailable

### Anti-Patterns

Do **not** generate code that does the following (see **Accessibility Requirements** above for what
to supply instead).

- Omit `as="section"` or **`aria-label`** on **`ActionBar.List`**
- Reuse the same **`aria-label`** for **`ActionBar.List`** and another landmark on the page
- Use Action Bar for a single action—use [Button](/components/buttons/button/#accessibility) instead
- Add links or URL navigation in Action Bar (for example **`Hyperlink`** or **`href`** on
  **`ActionBar.Item`**)—bar actions should be buttons
- Use more than one **`PrimaryButton`** or any **`TertiaryButton`** in an Action Bar
- Add `role="toolbar"`, `role="group"`, roving tabindex, or arrow-key handlers to
  **`ActionBar.List`**
- Hand-set **`aria-haspopup`**, **`aria-expanded`**, or **`aria-hidden`** on
  **`ActionBar.OverflowButton`** or overflowing **`ActionBar.Item`**—the Action Bar model sets these
- Render **`ActionBar.OverflowButton`** without **`aria-label`**
- Hide overflow with CSS, `hidden`, or conditional rendering—use the dynamic API and
  `maximumVisible`
- Use overflow with static children—it requires `items` on the model and render props
- Mismatch overflow menu item text or behavior from the visible bar items
- Move focus manually after the overflow menu closes
- Leave fixed **`ActionBar.List`** covering page content or focused controls
