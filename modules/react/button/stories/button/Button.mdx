# Canvas Kit Button

Clickable button elements that extend the native `<button>` element with Canvas styling.

[> Workday Design Reference](https://design.workday.com/components/buttons/buttons)

## Installation

```sh
yarn add @workday/canvas-kit-react
```

## Accessibility

The primary accessibility goal is a visible, programmatically determinable name on a native control that performs an in-page action (submit, open, dismiss, and similar). This page covers **`PrimaryButton`**, **`SecondaryButton`**, **`TertiaryButton`**, and **`DeleteButton`**.

Use [Hyperlink](/components/hyperlink/) when the control navigates to another URL or in-page location.

For [Toolbar](/components/buttons/toolbar/) icon and dropdown controls, see that component’s documentation. For a control that opens a menu, dialog, or expandable, see [Menu accessibility](/components/popups/menu/#accessibility), [Dialog accessibility](/components/popups/dialog/#accessibility), and [Expandable accessibility](/components/containers/expandable/#accessibility).

When users choose one value from **two or more** mutually exclusive options, use
[Segmented Control](/components/buttons/segmented-control/)—not a lone variant button. Use [Radio](/preview/inputs/radio/) when the selection needs radio semantics or native form submission.

See the [Button pattern (APG)](https://www.w3.org/WAI/ARIA/apg/patterns/button/) and Canvas Kit [Accessibility overview](/guides/accessibility/overview/).

### Minimum Accessible Structure

The following matches the [PrimaryButton](#primarybutton) examples: visible text for the default case, text plus a decorative icon, and an icon-only control with an accessible name.

```tsx
import {PrimaryButton} from '@workday/canvas-kit-react/button';
import {Tooltip} from '@workday/canvas-kit-react/tooltip';
import {plusIcon, relatedActionsVerticalIcon} from '@workday/canvas-system-icons-web';

<PrimaryButton>Save</PrimaryButton>;

<PrimaryButton icon={plusIcon}>Add item</PrimaryButton>;

<Tooltip title="Related Actions">
  <PrimaryButton icon={relatedActionsVerticalIcon} />
</Tooltip>;
```

For icon-only buttons, prefer **`Tooltip`** with **`title`** and default `type="label"` (which sets **`aria-label`** from **`title`** so sighted users also see the label). **`Tooltip`** with `type="label"` overwrites the wrapped control’s accessible name—use it on icon-only buttons only; visible button text already supplies the name. If the spec explicitly says not to use a tooltip, set **`aria-label`** on the button instead. The same patterns apply to **`SecondaryButton`**, **`TertiaryButton`**, and **`DeleteButton`**.

### Built-in Behaviors

Canvas Kit applies these automatically on **`PrimaryButton`**, **`SecondaryButton`**, **`TertiaryButton`**, and **`DeleteButton`**. **Do not duplicate them** in consuming code.

**ARIA and DOM** (_applied by button components_):

- **Variant buttons**: Render a native `<button>` (via **`BaseButton`**) with default **`type="button"`**. A passed **`type`** prop overrides that default—use **`type="submit"`** only when the button submits its form.
- **Visible label**: Button text is rendered in **`BaseButton.Label`** (`<span>`) inside the `<button>` so its text contributes to the accessible name.
- **`icon`**: Renders **`BaseButton.Icon`** (`SystemIcon`). Canvas Kit icon SVG markup uses `role="presentation"` and `focusable="false"`, so icons beside visible text are not announced separately.
- **`disabled`**: Maps to the native `disabled` attribute; disabled buttons are skipped in the tab order.
- **Focus**: Visible focus styling uses `:focus-visible`.
- **`ref`**: Forwards to the underlying `<button>`.
- **Native button attributes**: Standard props (for example `aria-label`, `aria-pressed`, `aria-expanded`, `id`, `onClick`) pass through to the `<button>` unless you change the element with **`as`**. Variant buttons do not set **`aria-pressed`** unless you pass it for a deliberate toggle design.
- **Popup triggers**: Variant buttons do **not** set `aria-haspopup` or `aria-expanded`. `Menu.Target`, `Expandable.Target`, and `Dialog.Target` own those per their docs.

**Keyboard** (_native `<button>` behavior_):

Variant buttons use native button keyboard support: <kbd>Tab</kbd> / <kbd>Shift</kbd>+<kbd>Tab</kbd> for focus order, and <kbd>Enter</kbd> or <kbd>Space</kbd> to activate.

**Screen reader expectations** (_when built-in behaviors are used as intended_):

- On focus, assistive technology announces the button name (visible text and/or `aria-label`) and role (for example, "Save, button").
- Icons rendered with **`icon`** next to visible text are not announced as separate images.
- Disabled buttons are announced as unavailable and are not in the tab order.
- When a variant button has `aria-pressed` and a stable visible label, assistive technology announces the name, “toggle button,” and pressed or not pressed (for example, “Bold, toggle button, pressed”).
- When a variant button is a popup **`*.Target`**, assistive technology follows that component’s documented popup and expanded behavior.

### Accessibility Requirements

Required in application code for an accessible button. Rows marked _(conditional)_ apply only when the situation matches—otherwise omit.

**If no design spec is provided:** use **`PrimaryButton`** with non-empty visible text and default **`type="button"`**. Omit **`icon`**, **`disabled`**, **`Tooltip`**, **`aria-label`**, custom **`id`**, **`as`**, **`type="submit"`**, and a **`ref`** unless the spec requires them.

| Requirement  | How to satisfy  |
| -------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Accessible name  | Non-empty visible text inside the variant button  |
| Icon-only name _(conditional)_         | **`Tooltip`** with `type="label"` and **`title`** on icon-only buttons (see [PrimaryButton](#primarybutton)), or **`aria-label`** when the spec explicitly says not to use a tooltip  |
| Variant choice                         | **`PrimaryButton`**, **`SecondaryButton`**, **`TertiaryButton`**, or **`DeleteButton`** per design; **`DeleteButton`** only for destructive actions  |
| Decorative icon _(conditional)_        | **`icon`** with visible text—meaning comes from button text  |
| Form submit _(conditional)_            | **`type="submit"`** on the variant button inside a form that should submit when activated; omit **`type="submit"`** otherwise (default **`type="button"`**)  |
| Mutually exclusive group _(conditional)_ | [Segmented Control](/components/buttons/segmented-control/) for two or more in-page mutually exclusive options—not a single variant button or lone on/off control; use [Radio](/preview/inputs/radio/) when the selection is a form value |
| Toggle pressed state _(conditional)_   | On/off controls: use **`aria-pressed`** only when the visible label stays stable while state changes (not Mute/Unmute-style labels); set **`aria-pressed`** in both states and include or ask the user for visual styling for pressed state—variant buttons do not provide default pressed visuals. Omit for one-shot actions (Save, Delete, Open). For a toolbar toggle, use **`ToolbarIconButton`**—see [Toolbar](/components/buttons/toolbar/)  |
| Menu trigger _(conditional)_           | Compose **`Menu`** with **`Menu.Target as={PrimaryButton}`** (**`Menu.Target`** defaults to **`SecondaryButton`**). Context menus: **`Menu.ContextTarget`**. See [Menu accessibility](/components/popups/menu/#accessibility) and **Menu trigger composition** below          |
| Related button groups _(conditional)_  | Semantic grouping (`<ul>` / `<li>` or `<fieldset>` / `<legend>`) when several buttons share one question or legend; each control still needs its own accessible name  |
| Disabled _(conditional)_               | Native **`disabled`** on the variant button when the spec marks the action unavailable  |
| Navigation _(conditional)_           | [Hyperlink](/components/hyperlink/) instead of a variant button when the action is navigation  |
| Programmatic focus _(conditional)_     | `ref` on the variant button and `focus()` only when the product must move focus after an action—omit by default  |

**Menu trigger composition** _(conditional)_:

**`Menu.Target`** renders the trigger—do not nest a variant button inside it. Use **`as`** for a different variant. Add **`Menu.Popper`**, **`Menu.Card`**, and **`Menu.List`** per [Menu accessibility](/components/popups/menu/#accessibility).

```tsx
import {PrimaryButton} from '@workday/canvas-kit-react/button';
import {Menu} from '@workday/canvas-kit-react/menu';

<Menu>
  <Menu.Target as={PrimaryButton}>Open</Menu.Target>
  {/* Menu.Popper, Menu.Card, Menu.List — see Menu accessibility */}
</Menu>;
```

**Summary for code generation:**

- **REQUIRED:** variant button with a non-empty accessible name (visible text for text buttons; for icon-only, **`Tooltip`** with `type="label"` preferred, or **`aria-label`** when the spec says not to use a tooltip)
- **CONDITIONAL:** **`icon`**; icon-only naming; **`disabled`**; **`type="submit"`**; **`Menu`** composition with **`Menu.Target as={…}`**; **`ToolbarIconButton`** / **`aria-pressed`** per toggle row; **`Hyperlink`** for navigation; grouping markup; programmatic focus via `ref`

### Anti-Patterns

Do **not** generate code that does the following (see **Accessibility Requirements** above for what
to supply instead):

- Use a `<div>`, `<span>`, `role="button"`, or other non-`<button>` with `onClick`, or suppress <kbd>Enter</kbd> / <kbd>Space</kbd> on a control that should act as a button—use **`PrimaryButton`**, **`SecondaryButton`**, **`TertiaryButton`**, or **`DeleteButton`** for native keyboard and assistive technology behavior
- Use a variant button when the action is URL navigation—use [Hyperlink](/components/hyperlink/)
- Leave icon-only buttons unnamed, rely on the icon alone, use **`Tooltip`** with `type="muted"`, or use **`aria-label`** when the spec allows **`Tooltip`** with `type="label"`—see **Icon-only name**
- Nest a variant button inside **`Menu.Target`**, or hand-set **`aria-haspopup`** or **`aria-expanded`** when **`Menu.Target`**, **`Expandable.Target`**, or **`Dialog.Target`** owns that state—use **`Menu.Target as={…}`** (and the matching popup docs) instead
- Set **`aria-pressed`** on one-shot actions (Save, Delete, Open) or on buttons whose visible label changes with state (for example Mute/Unmute)—see **Toggle pressed state**
- Use **`SegmentedControl`** for a single option or a lone on/off control—see **Mutually exclusive group**
- Use **`aria-disabled`** instead of native **`disabled`** on variant buttons
