# Canvas Kit Checkbox

Checkboxes allow a user to select zero, one, or multiple values from a predefined list of 7 or less
options.

[> Workday Design Reference](https://design.workday.com/components/inputs/checkboxes)

## Installation

```sh
yarn add @workday/canvas-kit-react
```

## Usage

includes a `<label>` with a `for` attribute referencing the underlying `<input type="checkbox">`

### Indeterminate

Set the `indeterminate` prop of the Checkbox to `true` to indicate the Checkbox is neither checked
nor unchecked.

A common use case for an indeterminate Checkbox is when the value of a parent Checkbox is dependent
on a number of child Checkboxes. The parent Checkbox is set to the indeterminate state if some (but
not all) of its children are checked.

<ExampleCodeBlock code={Indeterminate} />

> **Accessibility Note**: Use semantic unordered list markup so that screen readers can communicate
> the nested hierarchy of the components to users.

### Label Position Horizontal

Set the `orientation` prop of the wrapping FormFieldGroup to designate the position of the group

<ExampleCodeBlock code={LabelPosition} />

### Required

Set the `isRequired` prop of a wrapping FormFieldGroup to `true` to indicate that the field is
required. Labels for required fields are suffixed by a red asterisk.

<ExampleCodeBlock code={Required} />

### Error States

Set the `error` prop of the wrapping FormFieldGroup to `"caution"` or `"error"` to set the Checkbox
to the Alert or Error state, respectively. Render `FormFieldGroup.Hint` with the message text so
assistive technology can associate the hint with the group. Keep the Checkbox `label` so each
control retains its own accessible name; `FormFieldGroup.Label` only provides the group name.

The `error` prop may be applied directly to the Checkbox with a value of `"caution"` or `"error"` if
FormFieldGroup is not being used.

## Accessibility

Ensure each checkbox has a visible, programmatically determinable name, that checked, unchecked, and
mixed states are exposed to assistive technology, and that related checkboxes share a group name.
Use **Checkbox** when the user can select zero, one, or many independent options. For mutually
exclusive choices, use
[**Radio**](https://workday.github.io/canvas-kit/?path=/docs/preview-inputs-radio--docs) instead.
See [FormField's accessibility documentation](/components/inputs/form-field/#accessibility) for
shared group, hint, error, and required wiring.

### Minimum Accessible Structure

The following matches the [Basic Example](#basic-example): a **`Checkbox`** with a non-empty
**`label`**. **`FormFieldGroup`** is not required for a single standalone checkbox.

```tsx
import {Checkbox} from '@workday/canvas-kit-react/checkbox';

<Checkbox label="I agree to the terms" />;
```

### Built-in Behaviors

Canvas Kit applies these automatically on **`Checkbox`**. When related checkboxes are composed with
**`FormFieldGroup`** subcomponents, that grouping wiring is also applied automatically. **Do not
duplicate them** in consuming code.

**ARIA and DOM** (_applied by Checkbox_):

- **`Checkbox`**: Renders a native `<input type="checkbox">`. Canvas Kit assigns an `id` with
  `useUniqueId` unless you pass **`id`**.
- **`label`**: Renders a visible `<label htmlFor={id}>` so the control has an accessible name and
  clicking the text activates the input.
- **`indeterminate`**: Sets `aria-checked="mixed"` and the input's native `indeterminate` property.
  Otherwise `aria-checked` follows the **`checked`** prop.
- **`disabled`**: Maps to the native `disabled` attribute.
- **`ref`**: Forwards to the underlying `<input type="checkbox">`.

**Keyboard** (_native checkbox behavior_):

**`Checkbox`** uses native `<input type="checkbox">` keyboard behavior (tab order, Space to toggle,
and label activation). Do not add custom key handlers that prevent standard checkbox interaction.

**Screen reader expectations** (_when built-in behaviors are used as intended_):

- On focus, assistive technology announces the Checkbox **`label`** and checked, unchecked, or mixed
  state
- Disabled checkboxes are announced as unavailable

For group, hint, error, and required association, see
[FormField's Built-in Behaviors](/components/inputs/form-field/#built-in-behaviors).

### Accessibility Requirements

Required in application code for an accessible Checkbox. Rows marked _(conditional)_ apply only when
the situation matches—otherwise omit.

**If no design spec is provided:** use a visible Checkbox **`label`**. Omit **`FormFieldGroup`**
unless related checkboxes share a group name, hint, error, or required state. Omit
**`FormFieldGroup.Hint`**, **`isRequired`**, **`error`**, **`indeterminate`**, **`disabled`**, and a
custom **`id`** unless the spec requires them.

| Requirement                  | How to satisfy                                                                                                                                                                                                                                                                                                                                                                                                 |
| ---------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Accessible name              | Non-empty **`label`** on every **`Checkbox`**. **`FormFieldGroup.Label`** names the group only (`div` with an `id`); it is not a `<label>` and does not replace **`label`**.                                                                                                                                                     |
| Group wiring _(conditional)_ | When related checkboxes share a group name, hint, error, or required state: **`FormFieldGroup`** + **`FormFieldGroup.Label`** + **`FormFieldGroup.Input as={Checkbox}`**. Hint, error, caution, and required belong on the group — see [FormField accessibility](/components/inputs/form-field/#accessibility). When the design uses the visual caution or error ring, also set **`error`** on **`Checkbox`**. |
| Disabled _(conditional)_     | `disabled` on **`Checkbox`** when the spec marks the option unavailable. See [Disabled](#disabled).                                                                                                                                                                                                                                                                                                |

**Summary for code generation:**

- **REQUIRED:** non-empty **`label`**
- **CONDITIONAL:** **`FormFieldGroup`** wiring for related checkboxes, indeterminate, disabled. See
  [FormField accessibility](/components/inputs/form-field/#accessibility) for group hint, error,
  caution, and required.

### Anti-Patterns

Do **not** generate code that does the following (see **Accessibility Requirements** above for what
to supply instead):

- Manually set `aria-checked`, `id`, or `htmlFor` on **`Checkbox`** — Canvas Kit wires these
- Wrap a single standalone **`Checkbox`** in **`FormFieldGroup`** when there is no shared group
  name, hint, error, or related options — see **Minimum Accessible Structure**
- Wrap **`Checkbox`** with **`FormField.Input`** — when grouping related checkboxes, use
  **`FormFieldGroup.Input as={Checkbox}`** (see **Group wiring** in Accessibility Requirements)
- Omit **`label`** because **`FormFieldGroup.Label`** is present — the group label does not name the
  individual control
- Set `aria-checked="mixed"` without **`indeterminate`**, or invent mixed state in application ARIA
- Use **`aria-disabled`** instead of **`disabled`** — **`Checkbox`** maps unavailability to the
  native **`disabled`** prop
- Use **`disabled`** when users must still reach the control to hear why it is unavailable — keep
  the checkbox enabled and put that explanation in **`FormFieldGroup.Hint`**, or on an adjacent
  focusable control
- Use **Checkbox** for mutually exclusive choices — use
  [**Radio**](https://workday.github.io/canvas-kit/?path=/docs/preview-inputs-radio--docs) instead
