# Canvas Kit Radio

Radio Buttons allow a user to select one value from a predefined list of 7 or fewer options.

[> Workday Design Reference](https://design.workday.com/components/inputs/radio-buttons)

## Installation

```sh
yarn add @workday/canvas-kit-preview-react
```

## Usage

### Basic Example

Our radio component includes a `RadioGroup` container and `RadioGroup.RadioButton`, which renders an
individual radio button. Nest related `RadioGroup.RadioButton` buttons within a `RadioGroup` and
provide a `name` prop to the `RadioGroup` to group the radio buttons together. Each
`RadioGroup.RadioButton` must have a unique `value`. This value is used in conjunction with the
`value` prop set on the `RadioGroup` to determine which radio button is selected. To tie it all
together, provide an `onChange` handler to the `RadioGroup` to track the selected value as it
changes.

`RadioGroup` should be used in tandem with
[FormFieldGroup](/components/inputs/form-field/#accessibility). `FormFieldGroup.Label` names the
group, and `FormFieldGroup.Input` associates hint, error, and required state with each radio.

<ExampleCodeBlock code={Basic} />

Our example uses [React state](<(https://react.dev/learn/state-a-components-memory)>) to track the
value of the `RadioGroup`.

### Error States

Set the `error` prop of the wrapping `FormFieldGroup` to `"caution"` or `"error"` to set the group
to the alert or error state. Put the message in `FormFieldGroup.Hint`. `FormFieldGroup.Input`
associates that text with each radio.

## Accessibility

The primary accessibility goal is to ensure users can identify the radio group and each option,
determine which option is selected, and hear associated hints, errors, and required state when a
radio receives focus. Use **Radio** when the user must choose one option from a list. For independent options, use
[**Checkbox**](https://workday.github.io/canvas-kit/?path=/docs/components-inputs-checkbox--docs)
instead.

### Minimum Accessible Structure

The following matches the [Basic Example](#basic-example): a **`FormFieldGroup`** around a
**`RadioGroup`**, with two or more **`RadioGroup.RadioButton`** options.

```tsx
import {FormFieldGroup} from '@workday/canvas-kit-react/form-field';
import {RadioGroup} from '@workday/canvas-kit-preview-react/radio';

<FormFieldGroup>
  <FormFieldGroup.Label>Choose Your Pizza Crust</FormFieldGroup.Label>
  <FormFieldGroup.Field>
    <FormFieldGroup.List as={RadioGroup} name="pizza-crust" value={value} onChange={handleChange}>
      <FormFieldGroup.Input as={RadioGroup.RadioButton} value="deep-dish">
        Deep dish
      </FormFieldGroup.Input>
      <FormFieldGroup.Input as={RadioGroup.RadioButton} value="thin">
        Thin
      </FormFieldGroup.Input>
    </FormFieldGroup.List>
  </FormFieldGroup.Field>
</FormFieldGroup>;
```

Each option needs visible text and a unique **`value`**. The group needs a shared **`name`**, a
**`value`**, and **`onChange`**. Track the selected value in React state, as the
[Basic Example](#basic-example) does.

### Built-in Behaviors

Canvas Kit applies these automatically when you compose **`FormFieldGroup`** with **`RadioGroup`**.
**Do not duplicate them** in consuming code.

**ARIA and DOM** (_applied by `RadioGroup` and `FormFieldGroup`_):

- **`RadioGroup`**: Renders a `div`. It does not set `role="radiogroup"`. Radios that share
  **`name`** are one group.
- **`RadioGroup.RadioButton`**: Renders a `<label>` around `<input type="radio">` and the visible
  text. The wrapping `<label>` is the association, so an `htmlFor` pairing is not needed. That text is the option's accessible name, and clicking it selects the radio. 
- **`RadioGroup.Label`**: Passes **`disabled`** through to the input.
- **`RadioGroup.Label.Input`**: Sets **`name`** and the group's **`onChange`**. It sets **`checked`**
  and **`aria-checked`** when the input **`value`** matches the group **`value`**.
- **`ref`**: Forwards from **`RadioGroup.RadioButton`** to the `<input type="radio">`.

**Implementation note on `aria-describedby`:** **`FormFieldGroup.Input`** always sets
`aria-describedby="hint-{id}"`, and that value overrides **`aria-describedby`** on **`RadioGroup`**.
Render **`FormFieldGroup.Hint`** whenever there is hint, error,
caution, or required text. Omitting the hint leaves each radio pointing at a missing `hint-{id}`.

**`RadioGroup` `error`** only paints a box-shadow. It does not set `aria-invalid`. The
[Error States](#error-states) examples get both the ring and the accessible state from
**`FormFieldGroup`**.

**Keyboard** (_native radio behavior_):

**`RadioGroup`** uses native radio keyboard behavior. <kbd>Tab</kbd> moves to the selected radio, or
to the first radio when none is selected, and then leaves the group. Arrow keys move and select
within the shared **`name`**. Do not intercept these keys. Do not set **`disabled`** on the selected
radio. That removes the group's tab stop. See [Disabled](#disabled).

**Screen reader expectations** (_when built-in behaviors are used as intended_):

- On focus, assistive technology announces the group name from **`FormFieldGroup.Label`**, along
  with the option name, radio role, and checked state.
- When applicable, it also announces required state, invalid state (`error="error"`), and hint or
  error text. Caution does not set `aria-invalid`.
- Disabled radios are announced as unavailable.

For group, hint, error, and required association, see
[FormField's Built-in Behaviors](/components/inputs/form-field/#built-in-behaviors).

### Accessibility Requirements{/*CONTINUE HERE*/}

Required in application code for an accessible Radio group. Rows marked _(conditional)_ apply only
when the situation matches—otherwise omit.

**If no design spec is provided:** use a visible **`FormFieldGroup.Label`**, two or more
**`RadioGroup.RadioButton`** options with visible text and unique **`value`**s, and a shared
**`name`**, **`value`**, and **`onChange`** on **`RadioGroup`**. Omit **`error`**, **`isRequired`**,
**`FormFieldGroup.Hint`**, **`disabled`**, **`aria-describedby`** on **`RadioGroup`**, **`error`** on
**`RadioGroup`**, a **`ref`**, and **`StyledRadioButton`**.

**Choose a composition:**

- **`FormFieldGroup`** + **`RadioGroup.RadioButton`** — the default, matching the
  [Basic Example](#basic-example)
- **`RadioGroup.Label`** — only when the spec needs custom markup for the input and text. Keep it
  inside **`FormFieldGroup`**, with **`FormFieldGroup.Input as={RadioGroup.Label.Input}`**. See
  [Custom Radio Button](#custom-radio-button)
- **`StyledRadioButton`** — only when the spec requires a radio outside **`RadioGroup`**. You must
  supply **`name`**, **`checked`**, a real `<label>`, and a group label. See
  [Standalone Radio Button](#standalone-radio-button)

**Programmatic focus** _(conditional — omit by default)_:

Attach a **`ref`** only when the product must move focus to a radio after an action. Do not attach a
**`ref`** or call `focus()` unless the design or developer asks for it. See
[Ref Forwarding](#ref-forwarding).

| ---------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Group label and wiring                               | **`FormFieldGroup`** + **`FormFieldGroup.Label`** + **`FormFieldGroup.Field`** + **`FormFieldGroup.List as={RadioGroup}`** + **`FormFieldGroup.Input as={RadioGroup.RadioButton}`**. The group label is a `div` with an `id`; it does not name an individual option. Each option's name is the **`RadioGroup.RadioButton`** text. See [Basic Example](#basic-example).                                  |
| Shared name and unique values                        | **`name`**, **`value`**, and **`onChange`** on **`RadioGroup`**. | Hint, error, caution, or required _(conditional)_   | On **`FormFieldGroup`**, set only the props the spec includes: **`FormFieldGroup.Hint`** for hint, caution, or error text; **`error="caution"`** or **`error="error"`** for that state; **`isRequired`** when the group is required. Do not set **`aria-describedby`** or **`error`** on **`RadioGroup`**. See [Error States](#error-states), [Required](#required), and [FormField accessibility](/components/inputs/form-field/#accessibility). |
| Disabled _(conditional)_                             | **`disabled`** on **`RadioGroup.RadioButton`** when the spec marks that option unavailable. Never on the selected radio. See [Disabled](#disabled).                                                                                                                                                                                                                                                  |

| Custom input and text markup _(conditional)_         | **`RadioGroup.Label`**, **`FormFieldGroup.Input as={RadioGroup.Label.Input}`**, and **`RadioGroup.Label.Text`**, inside **`FormFieldGroup`**. See [Custom Radio Button](#custom-radio-button). |

**Summary for code generation:**

- **REQUIRED:** **`FormFieldGroup`**, visible **`FormFieldGroup.Label`**, **`FormFieldGroup.List
  as={RadioGroup}`** with **`name`**, **`value`**, and **`onChange`**, and two or more
  **`RadioGroup.RadioButton`** options with unique **`value`**s and visible text
- **CONDITIONAL:** on **`FormFieldGroup`**, only the states the spec includes —
  **`FormFieldGroup.Hint`**, **`error`**, or **`isRequired`**; **`disabled`** (not on the selected
  radio); programmatic focus via
  **`ref`**; **`RadioGroup.Label`** when the spec needs custom input and text markup. See
  [FormField accessibility](/components/inputs/form-field/#accessibility) for group hint, error,
  caution, and required.

### Anti-Patterns

Do **not** generate code that does the following (see **Accessibility Requirements** above for what
to supply instead):

- Manually set `role="radiogroup"`, `aria-checked`, `aria-invalid`, `aria-required`, or
  `aria-describedby` — **`RadioGroup`** wires `name`, `checked`, and `aria-checked`.
  **`FormFieldGroup.Input`** wires `aria-describedby`, `aria-invalid`, and `aria-required`
- Use **`FormField`** with `useFieldset`, or set `hintId` and `hintText` — group radios with
  **`FormFieldGroup`** and put the message in **`FormFieldGroup.Hint`**
- Wrap radios in **`FormField.Input`** — use **`FormFieldGroup.Input as={RadioGroup.RadioButton}`**
- Use [**Checkbox**](https://workday.github.io/canvas-kit/?path=/docs/components-inputs-checkbox--docs)
  for mutually exclusive choices
- Use **`StyledRadioButton`** unless the spec requires a radio outside **`RadioGroup`**. In that
  case supply **`name`**, **`checked`**, a real `<label>`, and a group label. See
  [Standalone Radio Button](#standalone-radio-button)
- Set **`disabled`** on the selected radio — keyboard users cannot move within the group. See
  [Disabled](#disabled)
- Rely on color alone for an error or caution — include **`FormFieldGroup.Hint`**. Use
  `error="error"` when the selection is invalid so `aria-invalid` is set. See
  [Error States](#error-states)
